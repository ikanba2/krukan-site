# ผลตรวจคำถามชิ้นงานและ API ตรวจงาน · ออกแบบและเทคโนโลยี ม.1

ตรวจวันที่ 18 ตุลาคม 2569 ครบ7บท23หัวข้อเขียนตอบ จากซอร์สหน้าเรียน แบบส่งงาน เส้นทางส่งข้อมูล และโค้ด API ของ GAS พร้อมทดสอบด้วยข้อมูลสังเคราะห์ใน Node VM **ไม่ได้เรียก API จริง ไม่อ่านงานนักเรียนจริง ไม่แก้หน้าเว็บและไม่ deploy ในรอบตรวจนี้**

ข้อสรุปคือควรแก้ทั้ง **คำถามที่เด็กเห็น โครงช่องตอบ และข้อมูล/เกณฑ์ที่ส่งให้ API** การเปลี่ยนถ้อยคำบนเว็บอย่างเดียวไม่ทำให้ตรวจยุติธรรมขึ้น ถ้าตัวตรวจยังไม่ได้รับโจทย์หรือหลักฐานที่เด็กแนบ

## ตัวอย่างปัญหาและคำถามที่ชัดกว่า

เดิมบท3ถาม “จะใช้ข้อมูลย้อนกลับแก้ปัญหาอย่างไร” และให้คำใบ้ “บอกว่าตรวจอะไร เมื่อใด และนำไปปรับส่วนใด” เด็กยังต้องคิดพร้อมกันทั้งความหมายข้อมูลย้อนกลับ ระบบของตน และรูปแบบคำตอบ

เสนอแยกเป็น:

1. คุณจะตรวจของก่อนเก็บหรือหลังคืน? เลือกหนึ่งจังหวะ
2. จะตรวจสิ่งใด และรู้ได้อย่างไรว่าของไม่ครบ?
3. ถ้าพบว่าไม่ครบ คุณจะทำอะไรต่อ?

ให้แนวเริ่มตอบ “หลังจาก… ฉันตรวจ… โดย… ถ้า… จะ…” เป็นทางเลือก เด็กเขียนตารางหรือวาดผังก็ได้ ตัวอย่างต้องเป็นคนละระบบ เช่นการคืนหนังสือ ไม่ใส่คำตอบสำเร็จของชิ้นงานเด็ก

เดิมบท2ถาม “เหตุใดจึงเกิดการเปลี่ยนแปลง” แต่บทเรียนยกการซักผ้า ขณะที่งานส่งเป็นลิ้นชักกับถาด ควรบอกให้ชัดว่า **ข้อนี้ให้ใช้สองวิธีจัดของที่คุณเพิ่งเปรียบเทียบ** ไม่ใช่ตอบประวัติการเปลี่ยนเทคโนโลยีทั้งหมด

เดิมบท5ให้เลือก “กลไกหรือวงจร” แต่ไม่มีเส้นทางคำถามเฉพาะ ควรเลือกทางก่อน แล้วแสดงคำถามตรงทางนั้น เช่นวงจรให้บอกการต่อครบ/สวิตช์เปิด–ปิด ส่วนกลไกให้บอกแรงและการเคลื่อน ไม่บังคับทำทั้งคู่

ร่างครบ23หัวข้ออยู่ใน [WORK_GUIDANCE_PROPOSAL_V1.md](WORK_GUIDANCE_PROPOSAL_V1.md) และข้อมูลสำหรับ AI ทำต่ออยู่ใน [WORK_GUIDANCE_PROPOSAL_V1.json](WORK_GUIDANCE_PROPOSAL_V1.json)

## API ปัจจุบันทำอะไรจริง

มีทั้งปุ่มให้ครูขอร่างรายคนและระบบตั้งเวลาร่างอัตโนมัติทุก5นาทีเมื่อครูเปิดใช้ แต่ผลยังเป็น **ร่างรอครูยืนยัน** ไม่ใช่ระบบเผยแพร่คะแนนสุดท้ายให้เด็กอัตโนมัติทันที ต้องคงจุดยืนยันของครูไว้

เส้นทางปัจจุบัน: `workFields` → `submitted()` เก็บ fields/labs → `cloud.js` ส่ง `pushSubmission` → โหมด manual หรือ `dtAutoDraftTick()` → `dtAiCore_()` → Gemini → AiDrafts/หน้าครู → ครูยืนยัน → ผลถึงเด็ก

โค้ดที่ยืนยันปัญหา:

- `app.js` ส่วน `workFields`, `work()`, `submitted()` และ `aiDraft()` ใช้ชื่อหัวข้อ+คำใบ้สั้น แต่ส่งไป API เฉพาะชื่อหัวข้อ ไม่ส่งคำใบ้
- `teacher-queue.js:13` รวม labels ทุกบทใน object เดียว คีย์ `problem` ของบท1ถูกทับด้วยชื่อช่องบท6 การเรียก manual รายคนใช้ labels ของบทนั้นจึงไม่เจอการทับแบบนี้
- `Code.gs:316–319` อ่าน `pl.fields` เท่านั้น ไม่อ่าน `pl.labs`; จำกัดต่อช่อง1500และรวม9000; user prompt มีชื่อ rubric กับข้อความงาน ไม่มี assignment/starter/requirements/acceptance หรือคำอธิบายระดับคะแนน
- `Code.gs:278` เป็นต้นไป มีข้อความ “ถ้าไม่มีหลักฐานหรือเขียนสั้นเกินไปให้ให้คะแนนต่ำ” ต้องแยกไม่มีหลักฐานจริงออกจาก APIยังไม่ได้รับหลักฐาน และตัดเงื่อนไขลงโทษจากความสั้น
- `Code.gs:333` ใช้ `Number(...) || 0` จึงกลบคะแนนขาด/ข้อความที่ไม่ใช่ตัวเลขเป็น0 และ clamp ค่าหลุดช่วงแทนปฏิเสธผลไม่สมบูรณ์
- `cloud.js` ฟังก์ชัน `labsForSend()` ตัด strokes ออกเมื่อ lab payload ใหญ่เกิน60000อักขระ: ครูอาจไม่เห็นแบบวาดในฉบับออนไลน์ได้ด้วย ควรเก็บไฟล์หลักฐานแยกแทนตัดทิ้งโดยเงียบ
- `dtAutoDraftTick()` ใช้ has จาก AiDrafts ทุกสถานะ งานที่ได้ error บางประเภทจึงไม่ถูกเลือกลองใหม่อัตโนมัติในรอบถัดไป ต้องมี retry ที่เห็นสถานะชัด โดยไม่สร้างคะแนนให้เด็กเมื่อระบบขัดข้อง

การอ้างข้างต้นเป็นซอร์สในเครื่อง ณ วันที่ตรวจ README ของ GAS ระบุ deploy version4แล้ว แต่รอบนี้ไม่ได้ยืนยันโค้ดที่กำลังรันใน deployment หรือค่า API key/trigger จริง

## สัญญาข้อมูลใหม่ที่ควรใช้ก่อนให้ AI ตรวจ

ควรมีข้อมูลกลาง `WORK_TASK_SPEC` ที่หน้าเด็ก ครู และ APIอ่านฉบับเดียวกัน และเก็บ taskVersion/rubricVersion ไว้กับฉบับส่งงาน ไม่ใช้ config ล่าสุดตีความงานเก่าโดยเงียบ

```json
{
  "chapterId": "DT-M1-C03",
  "taskVersion": "work-v2",
  "rubricVersion": "rubric-v2",
  "task": {"assignment": "...", "constraints": [], "allowedPaths": []},
  "questions": [{"questionId": "DT-M1-C03-WORK-feedback", "prompt": "...", "expectedElements": [], "answer": "..."}],
  "evidence": [{"evidenceId": "lab-01", "source": "saved-lab", "status": "available", "values": {}, "reason": "..."}],
  "unavailableEvidence": [{"evidenceId": "sketch-01", "reason": "image-not-supplied-to-model"}],
  "rubric": [{"criterionId": "c03-r2", "maxScore": 25, "questionIds": [], "evidenceIds": [], "descriptors": {}}],
  "integrity": {"truncated": false}
}
```

ข้อมูลที่คำนวณตรง ๆ ได้ เช่นงบรวม ขนาดภายนอก หรือจำนวนรอบ ให้คำนวณด้วยโค้ดจากค่าที่มีและส่งผลตรวจที่มีที่มาให้ AI ช่วยอธิบาย ส่วนความเหมาะสม เหตุผล และข้อเสนอหลายคำตอบใช้ rubric + ครู ไม่จับคำสำคัญตัดคะแนนความเข้าใจ

ถ้า AIไม่ได้รับภาพ ให้ส่งเพียงข้อมูลมิติที่มีจริง และติดสถานะว่าไม่ได้ตรวจภาพ ไม่อ้างว่าแบบวาดสอดคล้องกับค่าที่พิมพ์โดยไม่ได้เห็นภาพ การเพิ่มการอ่านภาพภายหลังต้องทดสอบเส้นทางไฟล์/สิทธิ์และความสามารถโมเดลก่อนใช้

ผลตอบกลับควรเป็นรายการตาม criterionId มีคะแนนหรือ `null` พร้อมสถานะ หลักฐานที่อ้าง และเหตุผล ไม่ใช้ array ที่ขาดแล้วเติม0 เช่น:

```json
{
  "status": "needs_teacher_review",
  "criteria": [{"criterionId": "c03-r2", "score": null, "status": "evidence_unavailable", "evidenceRefs": [], "reason": "แบบร่างที่เด็กอ้างยังไม่ได้ส่งให้ตัวตรวจ"}],
  "studentFeedback": {"strength": "...", "clarify": "...", "nextStep": "..."}
}
```

แยกให้ได้อย่างน้อย4กรณี: คำตอบผิดจริง / เด็กยังไม่ได้ทำ / หลักฐานเด็กมีแต่ระบบมองไม่เห็น / APIตอบผิดรูปแบบ สองกรณีหลังไม่ใช่คะแนน0ของเด็ก ครูพิจารณาหลักฐานและเป็นผู้ยืนยันคะแนนสุดท้าย

## เกณฑ์คะแนนที่ต้องเขียนเพิ่ม

คงน้ำหนักแต่ละบทเดิมไว้ก่อน แต่ทุกเกณฑ์ต้องมี (1) ดูจากคำถาม/หลักฐานใด (2) อะไรคือครบ (3) แบบไหนได้บางส่วน (4) อะไรผิดหลัก (5) เมื่อไรยังประเมินไม่ได้

ตัวอย่างบท3เรื่องข้อมูลย้อนกลับ: ครบเมื่อระบุสิ่งที่ตรวจ จังหวะตรวจ ผลที่ได้ และการนำผลไปปรับการทำงานสัมพันธ์กัน; บางส่วนเมื่อมีผลตรวจแต่ยังไม่บอกว่าจะนำไปทำอะไร; ผิดหลักเมื่อสับสนผลผลิตกับผลตรวจและอธิบายความสัมพันธ์ไม่ได้; ยังประเมินไม่ได้เมื่ออ้างผังที่ APIยังไม่ได้รับ ต้องเปิดให้ครูดู ไม่ปักคะแนน0

ตัวอย่างบท5ความปลอดภัย: ต้องถามประเด็นนี้บนหน้าเด็กก่อน แล้วพิจารณาความเสี่ยง/การป้องกันเฉพาะทางที่เด็กเลือก ไม่บังคับอธิบายวงจรหากเลือกกลไก และไม่ใช้ความยาวข้อความเป็นเกณฑ์

## รูปแบบหน้าชิ้นงานที่เสนอ

บนสุดแสดง “งานนี้ทำอะไร / ใช้ข้อมูลชุดไหน / ส่งอะไร / ครูดูอะไร” เป็นภาษาสั้นชัดเจน จากนั้นแยกการ์ดคำถามเป็นขั้น แต่ละการ์ดมีคำถามย่อย1ประเด็นต่อช่อง ตัวเลือกเปิดแนวเริ่มตอบ ตัวอย่างคนละงาน และหลักฐาน lab ที่เลือกอ้างได้ ตารางใช้ช่องตารางจริง ไม่ให้เด็กพิมพ์ตารางใน textarea เอง

มีทางเลือกตอบข้อความ/ตาราง/อ้างผังที่บันทึกตามเนื้อหา ก่อนส่งแสดงรายการตรวจความครบแบบเจาะจง เช่น “ยังไม่บอกสิ่งที่ตรวจหลังคืน” แทน “กรอกให้ครบ” คำแนะนำก่อนส่งตรวจความครบเท่านั้น ไม่เปิดคำตอบหรือให้คะแนนก่อนลงมือ

ขั้นดำเนินการที่ปลอดภัยกับงานเดิม: เพิ่ม task schema/ร่างคำถาม → ยืนยันข้อมูล4/6ชิ้นและสถานะงาน → เชื่อม rubric/AI จาก schemaเดียว → ย้ายร่างเก่าโดยคง legacy keys และ version → ทดสอบกรณีจริง/จำลอง/ยังไม่ทำ/แนบภาพ/APIล้มเหลว → ตรวจข้อความบนเว็บ → buildและdeployเมื่อดำเนินการแก้แล้ว
